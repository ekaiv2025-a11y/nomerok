# Страницы «Грузия» (путеводитель для жизни и отдыха) — инструкция для задачи по расписанию

Страница города — файл `data/geo/<id>.json`. Образец — `data/geo/batumi.json`: повтори его структуру и уровень детальности.
Сайт сам строит из файла: страницу города `/ru/georgia/<id>`, таблицу погоды `/weather` и 12 страниц «Погода в … в <месяце>».

## Порядок
1. `git pull --rebase`. Прочитай `data/geo/batumi.json`, `lib/geo.ts` (тип `GeoPage`) и `scripts/news-bot.md` (общие правила: без политики, факты только из источников, своими словами, без «ИИ-звучания»).
2. Возьми первую строку без `[x]` в `scripts/geo-topics.txt`.
3. Сначала подборка сборщика по городу: `node scripts/feed.mjs list --hours 96 --q <город>` — свежие новости и факты.
4. Исследуй: Википедия (ru и en), официальные сайты мэрии и туризма (georgia.travel, adjaratourism.ge и т. п.), сайты транспорта (railway.ge, tkt.ge, аэропорты), климат — climatestotravel.com/climate/georgia/<город> (или таблица «Климат» в Википедии; источник указать в `climate.source`). Посмотри 2–3 первых русских путеводителя Google по городу — чтобы наша страница была полнее и полезнее, но ничего не копируй.
5. Заполни файл:
   - `id` — из очереди; `kind`; `name`, `nameIn` («в Сигнахи»), `nameGen` («Сигнахи»: «районы Сигнахи», «погода Сигнахи»); `region`.
   - `title` до 110 знаков (как ищут: «Сигнахи: путеводитель — что посмотреть, погода, как добраться»), `description` 80–200.
   - `lead` — 3–4 предложения: что за место и кому полезна страница (и тем, кто едет на пару дней, и тем, кто живёт).
   - `facts` 5–9 строк (регион, высота над морем или море, климат, когда ехать, как добраться коротко, валюта/часовой пояс — только проверенное).
   - `sections`: `about` (обязательно), `getthere` (как добраться — из Тбилиси, Батуми, Кутаиси; время в пути; где купить билеты; без точных цен, если не уверен в их свежести), `transport` (по городу), `life` (жизнь и аренда — для крупных городов; ссылки на наши статьи `/ru/guide/<slug>` только существующие), `food` (местная кухня, вино). Блоки — как в журнале: `p`, `list`, `tip`, `cta` (с `cat` из каталога), `link`.
   - `districts` — для городов (4–8 районов с честными плюсами и минусами); для курортов — части курорта или ближайшие посёлки.
   - `sights` 6–12: `name`, `text` (1–2 фразы своими словами), `lat`/`lng` (из Википедии/OpenStreetMap — сверяй, точки должны быть в Грузии), `photo` — что искать на Wikimedia Commons по-английски, `guide` — slug нашей статьи «Куда поехать», если есть.
   - `climate.months` — 12 месяцев: `tmin`, `tmax`, `rain` (мм), `rainDays`, `sun` (часов за месяц, если есть), `sea` (только для моря). Цифры — из источника, не округляй до выдумки.
   - `months` — 12 строк: `what` (чем заняться в этом месяце именно здесь: сезон, фестивали, сбор урожая, лыжи, купание) и `wear` (что надеть и взять).
   - `faq` 4–7 реальных вопросов («когда ехать», «как добраться из Тбилиси», «где остановиться», «сколько дней нужно»…).
   - `sources` 3–8 (сначала официальные), `updated` — сегодняшняя дата.
6. Подключи файл в `lib/geo.ts`: `import XXX from "@/data/geo/<id>.json";` и добавь `XXX as unknown as GeoPage` в массив `GEO`.
7. `node scripts/check-geo.mjs` и `npx tsc --noEmit -p .` (если нет node_modules — `npm ci`) — исправь все ошибки.
8. Поставь `[x]` в `geo-topics.txt`. Коммит `data/geo/<id>.json`, `lib/geo.ts`, `scripts/geo-topics.txt` и пуш в main с повтором при ошибке сети:
   `for i in 1 2 3 4; do git push -q origin main && break; sleep $((2**i)); git pull --rebase -q; done`
9. В конце коротко: город, сколько слов, сколько достопримечательностей, источники.

## Правила
- Только проверенные факты. Сомневаешься в цифре или часах работы — не пиши её.
- Без «лучший», «самый вкусный», без выдуманных отзывов и цен.
- Пиши просто и живо, как знакомый, который здесь живёт.
- Для регионов (`kind: "region"`) `climate` и `sights` можно опустить; вместо них — разделы о городах региона со ссылками `/ru/georgia/<id>`.
